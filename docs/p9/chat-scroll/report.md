# 聊天滚轮与存档通知

用户指出滚轮上下滚动聊天有明显迟滞，并明确要求删除“其他页面正在保存”和“进度已保存在此浏览器中”两类自定义系统通知。

## 原因与处理

每次聊天重绘都会重新拼接并换行全部历史，包括滚轮、鼠标悬停、输入及50ms定时重绘。100条长中文记录的隔离压力样本中，单次重复重绘约35–89ms，滚轮事件排队约128–246ms。长无空格中文的重复测宽、整段换行占用主线程，不是保存锁延迟后才允许滚动。

按消息身份和逻辑宽度缓存原生换行/组件偏移，并复用最后100行的布局；新消息只测量自身，宽度变化重新布局。淡出按当前时间计算，不缓存消息透明度。滚轮立即累计偏移，悬停、滚轮和光标定时更新合并到下一次浏览器帧；同步绘制和卸载取消待执行帧。画布只在尺寸变化时重分配，其余绘制显式清空，保留此前物理像素清晰度处理。

相同压力样本、无并发测试负载时，重复重绘约3–7ms。该数据来自真实GameChat与原生鼠标滚轮，但历史为合成压力样本，并有只读计时包装；不能作为目标电脑的人工体验或帧率保证。正式浏览器回归另用普通构建和原生键盘输入创建历史，不修改聊天实例。

## 删除的通知

普通就绪状态不再进入自动聊天；`lock-busy`在自动聊天与主页启动反馈中静默。仍记录静默恢复边界，避免错误去重吞掉之后的真实失败。Web Locks、超时、有限事务、存档锁及可点击的重试保留，不以删除文案取消并发保护；真实保存写入/损坏/操作失败仍有反馈。

本次没有修改中文文案草稿、场景、鼠标锁定或存档格式。

## 验证

规则覆盖旧历史不重复测宽、新消息/宽度变化失效、样式偏移、多行顺序、连发滚轮单帧合并、上下限与卸载取消、静默恢复后真实错误再次显示。正式root与Pages路径使用浏览器原生键盘创建长中文历史，检查正反滚轮、Shift、PageUp/PageDown，并用真实跨页面Web Lock等待和恢复验证两类通知不出现、库存保持。性能采样、原生输入及实体检查分开记录；没有操控实体桌面或进行人工听感验收。

当前工作区全套734项规则测试与48项相关定向回归通过，TypeScript及双路径正式构建/资源审计通过。[正式浏览器记录](evidence/browser-results.json)确认两条路径滚动偏移7→14→7→8→7→0，真实锁等待与恢复均静默，隔离注入写入失败仍显示红色错误，库存保持。记录区分主线程收到滚轮后的重绘响应和浏览器投递前排队；软件3D渲染下的排队值不作为目标电脑端到端延迟结论。[绘制压力采样前](evidence/profile-before.json)与[采样后](evidence/profile-after.json)保留合成记录和计时方法。
