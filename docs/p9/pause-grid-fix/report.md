## BGM后台与雷雨加速

- GameMusic不再因document.hidden取消媒体/异步加载。BGM媒体及原版曲间计时独立于D08游戏模拟，用后台低频音乐调度；主/分类Off、重置、导航卸载仍取消并释放对象URL、节点、待完成加载。跨标签设置同步仍能在隐藏时应用Off。设备、作物、游戏天气仍按D08暂停，不借音乐恢复后台生产。
- 当前IAB创建另一个标签后原页document.hidden仍false，故该环境的双标签操作不能算真实后台通过。生产GameMusic隐藏状态、加载及Off/销毁由规则回归验证；真正浏览器后台音频仍需用户试听。没有用合成可见性事件冒充可信输入。
- 普通构建实际执行/weather thunder 10d、/tick sprint 1d。[修正前记录](evidence/storm-before.json)最后100次天气调度仅跨1080.5ms（约92.55次/秒），同批audioTime大量相同；雨sample约2秒。这证明存在调度洪峰，不将它直接等同于OS/设备全部失声根因。
- 修正天气音频请求及解码后的开始阶段：同一实际客户端50ms内合并同类雨/雷事件，阻止补进度声音排队挤到一个播放时刻；同一路径共享单次fetch/decode；静态播放源上限256，耗尽拒绝新源且释放后可继续。只影响瞬时音频呈现，不删游戏tick、不改天气随机数据、加工产量、作物或发现顺序。此为依据用户自主执行授权作出的有界调度工程决定，不声称完全复刻所有设备OpenAL配置。
- [同样命令修正后记录](evidence/storm-after.json)：最近100次请求中86次合并、14次实际调度，观测时voices2、decoding0；音乐ebb播放到287.48秒，context running，实际audioTime持续推进。该窗口与修正前不是固定等长性能基准，不用百分比冒充FPS或人工听感改善。人工确认卡顿/失声是否消除仍待试听；原104.2/545.6ms未确定峰值结论不变。
