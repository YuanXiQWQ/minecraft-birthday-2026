## 3. 画面设计

进入 Cave 后，玩家处于一段低矮洞道内部。视线前方偏左是带有煤与铁的错层石壁，右侧是一块可供摆放设备的自然石地面。两处柔和火把光照出工作范围，后面的窄洞越过一道石肩后向左转暗。顶部和两侧的岩体包住画面，地面保持连续。

画面只有一个主视觉焦点：左前方采矿凹室。右侧空地承担使用功能，深部洞道承担环境纵深。

| 部位 | 造型 | 视觉作用 | 实现要求 |
| --- | --- | --- | --- |
| 前缘洞顶 | 净高以 2–3 格为主，边缘呈不对称台阶 | 让视角确实位于洞内 | 不做贯穿全宽的等高大平顶；不遮住矿脉和设备 |
| 左前矿脉凹室 | 低处凸出的石台、后侧石肩、侧壁凹槽 | 形成集中可读的采矿区 | 现有自然来源独立保留，邻接石壳不侵入来源单元 |
| 右前工作袋 | 连续、相对平整的天然石地面，保留可用净高 | 容纳玩家自己摆放设备 | 不预放设备；不画限定区域；不改变合法放置规则 |
| 后方洞道 | 主要 2–3 格高，窄口后向左折 | 让空间在视线之外继续延伸 | 弯道由真实岩体遮挡，不能用黑色平面封口 |
| 右侧木支撑 | 少量橡木竖向与横向构件嵌在外侧岩壁 | 提供轻微人工整理痕迹 | 不能形成挡在中央的门框，不能埋住旧设备 |

### 洞体细节

- 石壁上的凸出、凹槽、台阶以完整方块尺度形成。维持原版纹理的单格尺度，不将一张纹理拉伸覆盖整面墙。
- 矿脉后侧与左侧补连贯的岩体，令其看起来从石壁中露出，避免一排独立展示方块的感觉。
- 前缘、矿脉凹室与后段的洞顶高度略有变化。局部凹室可有 4 格顶高，仍保持低洞道的总体尺度。
- 左侧低台与石头来源自然衔接；工作袋地面保持平整。不要为视觉碎石随意堆满可操作地面。
- 后方洞道先显示一个较暗的侧壁，再被更深的石肩挡住视线。尾部保持有轮廓的暗灰，而非一片没有几何层次的纯黑。
- 不添加远处的装饰煤矿或铁矿，避免出现看起来可采却没有来源身份的矿石。

### 配色和材质

石灰灰是大面积基色，煤黑和铁矿浅褐是主要识别色，橡木棕与火焰只占小面积。保持原版像素贴图与硬边结构。优先用空间层差打破单调，不用高频随机换色、棋盘式多材质或写实石材。

本轮不加入繁茂洞穴植被、水池或岩浆。场景的采矿身份由岩体、矿脉、火把与少量木支撑表达。

## 5. 资源节点保持不变

当前共 12 个自然来源：5 个石头、3 个煤矿、4 个铁矿。保持来源 ID、数组顺序、坐标和类型，不将它们合并进静态石壳。

| 来源 ID | 坐标 |
| --- | --- |
| stone:0 | [-6, 0, -3] |
| stone:1 | [-5, 0, -3] |
| stone:2 | [-4, 0, -3] |
| stone:3 | [-6, 1, -4] |
| stone:4 | [-5, 1, -4] |
| coal_ore:0 | [-4, 1, -5] |
| coal_ore:1 | [-3, 0, -4] |
| coal_ore:2 | [-3, 1, -5] |
| iron_ore:0 | [-2, 0, -4] |
| iron_ore:1 | [-1, 0, -4] |
| iron_ore:2 | [-2, 1, -5] |
| iron_ore:3 | [-1, 1, -5] |

重要语义：

1. ID 由同类来源数组索引生成；重新排序会改变 ID 对应位置，破坏已有 removed 事实的含义。
2. 自然来源继续位于 AuthoredWorld.natural，保留 node: 前缀的射线身份。
3. 静态石壳不得与来源占用同一个单元，也不能盖住所有可见采集面。
4. 默认画面先看见前层、采掉后再露出后层是可以接受的；12 个来源必须在既有允许视角内逐层可达。
5. 全部采完后应留下自然的凹口，不能暴露“没有厚度的贴片墙”或空白画布。

### 采集、恢复与设备占格

- 工具、硬度、采集时长、掉落、背包容量、长按连续挖掘、裂纹、粒子与声音沿用已有系统。
- 错误工具可以破坏来源但没有合格掉落，这是当前规则。不要改成无工具时完全无法破坏。
- 刷新当前洞穴保留本次 removed。
- 切到其他场景后再进入洞穴，按既有 visit epoch 规则恢复天然来源；重复选中当前洞穴不恢复。
- 已放设备、设备内容和其他持久变化不因返回而重置。
- 若已采空的来源单元被玩家设备占据，返回后该设备继续占格；不能用恢复的来源或新背景覆盖它。

## 6. 光照设计与技术实现

### 视觉目标

两支火把分别服务矿脉凹室与右侧作业地面。它们是固定环境装饰，进入场景已经存在。火焰本身亮，周边石壁和地面确实变亮，暖色保持克制。

明暗次序：

1. 矿脉和工作地面最容易看清。
2. 近处侧壁次之。
3. 洞顶和外围石肩较暗。
4. 后方弯道最暗，但仍有边缘与层次。

矿物使用原版材质辨认，不添加煤矿/铁矿自身发光、闪光描边、漂浮名称或任务箭头。火把光不等同于原版精确动态彩光复刻；少量暖色属于本轮美术选择。

可用以下相对强度作为调参起点，最终以实际画面为准。这些不是 Minecraft 光照等级，也不是已经实测的视觉标准：

| 区域 | 相对自身原始面明暗的系数起点 |
| --- | --- |
| 火把邻近面、主要矿物可见面 | 0.82–1.00 |
| 工作地面与主要中景 | 0.65–0.85 |
| 外围侧壁与洞顶 | 0.35–0.60 |
| 后段弯道 | 0.18–0.32 |

必须结合当前颜色空间、朝向顶点明暗和贴图实际显示校准；不能把表中数字直接当作最终屏幕亮度。

### 已确认的实现陷阱

当前 VanillaModels 使用共享 MeshBasicMaterial，主要明暗来自原版纹理和朝向顶点色。SceneView.applySkyLighting 对 cave 固定 factor=1、rgb=[1,1,1]。

因此，仅在场景中添加 PointLight 不能让现有石壁响应火把。Three.js 官方说明明确指出该材质不受灯光影响：[MeshBasicMaterial](https://threejs.org/docs/pages/MeshBasicMaterial.html)。

采用与现有材质体系兼容的洞穴专用局部明暗方案。优先复用实例色或洞穴专用顶点色，在原始面色基础上计算，不改成全局 PBR，不重做整个渲染器，也不使用全屏黑色蒙版替代几何光照。

实现要求：

- 颜色来源按世界坐标与洞穴照明配置确定；石壳、矿脉和洞穴内的玩家设备表现一致。
- 不能直接持久修改共享 stone 或全局材料缓存，导致平原、农场或家被染暗、染黄。
- 保存原始颜色，并从原始颜色重新计算。重复同步不能累乘到越来越黑。
- 洞壳因设备布局变化重建、自然来源因采集或重新进入而重建后，都重新应用同一套明暗。
- 现有 applySkyLighting 不能每帧把局部明暗覆盖掉。
- GUI、物品图标、选中反馈、裂纹与破坏粒子仍可辨认，不对整个页面做调色。
- 固定照明可在几何建立或布局改变时计算；不要每帧重建洞体或重建大量材质。
- 火焰若使用动画，接入既有生命周期；这轮无需额外的动态阴影、体积光或高强度闪烁。

## 7. 新装饰资源与占用

当前 world-manifest 并不因为物品图标存在，就自动提供可实例化的对应方块。壁挂火把须按 Java 26.3 的原版 blockstate、模型、贴图、朝向、透明采样和现有清单流程接入，正常纳入资源哈希检查与普通构建。

不可从参考截图裁纹理，不将 AI 效果图作为运行背景，也不通过外链图片替代原版方块模型。

### 火把

- 一支位于矿脉侧边的岩面，一支位于右侧作业袋的外缘。
- 锚点选择必须由生产射线与旧设备兼容检查决定，不能仅凭截图摆放。
- 薄火把、火焰和光效不能被当作完整方块的顶面支撑。
- 装饰实体的实际占用与渲染应一致；透明像素与遮挡继续走已有材质接受逻辑。
- 粒子和纯光效不拦截采矿或设备拾取。
- 火把的承载墙面若因为旧设备兼容而被移除，对应火把和光源必须同步处理，避免悬空火把或无来由的亮斑。

### 木支撑

右侧外墙使用少量现有橡木模型形成竖向支撑和短横梁，尽量替换或嵌入原本属于洞壳的单元。不要横跨主要可视窗口，不将主区域变成木制走廊。

真实实体需参与结构与放置判断。不能出现可见木柱却允许设备穿入，也不能出现没有几何对应的整片禁建区。

### 旧设备保护

caveRockCells(stations, eye) 当前会为落入新增洞壁的旧设备保留邻域和可视通道。此保护目前只影响石壳。

本轮必须让新增木支撑、火把及其光源也遵守这套兼容保护：

- 不移动、不删除、不清空任何旧设备。
- 旧设备布局变化后，石壳、装饰可见性和照明一起同步。
- 装饰与旧设备或其保留视线冲突时，撤掉或调整冲突装饰。
- 支撑关系一起更新，避免火把悬空、横梁孤立。
- 不放宽新的设备穿墙放置权限。

## 9. 验收要求

### 视觉

- 默认机位能读出低顶入口、左侧采矿凹室、右侧工作袋、后方转暗洞道四层关系。
- 矿脉有贴近岩体的嵌入感，不能像独立展品。
- 地面、侧壁、顶面有可辨明暗，深处形成纵深，主要目标在普通亮度显示器上易辨。
- 两支火把的邻近石壁确实受局部明暗影响；不是只画两个亮火焰。
- 新档右侧为空地。玩家放置设备后，设备自然融入场景。
- 横屏和窄屏仍为同一真实 3D 空间，保持已有视角策略。

### 采矿与放置

- 使用生产 SceneView.pick 与实际几何验证 12 个来源按前后层全部可达。
- 验证全未采、部分采空、全部采空三种形态。
- 验证刷新保留采空状态，跨场景返回按旧合同恢复。
- 在采空的合法来源单元放设备后返回，设备与矿物不重叠。
- 验证右工作袋可放置、使用、旋转和拆除既有设备，相关邻接传输仍成立。

### 照明与生命周期

- 石壳与自然来源重建后亮度一致，没有累乘变黑。
- 矿物不突然回到全亮。

- 其他三个场景和 GUI 不受洞穴颜色污染。
