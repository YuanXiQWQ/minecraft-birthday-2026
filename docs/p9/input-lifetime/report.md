# 鼠标默认锁定、浏览器快捷键与保存画面

用户明确取消手动唤出鼠标。Ctrl + 右键不再切换所有权，保留普通 Use 及物品栏的 Ctrl 语义。中英文系统教程与第八条作者消息改为打开背包/暂停唤出鼠标，作者 3 秒首条、随后每隔 5 秒的节奏保留。

世界首次就绪及从 GUI 返回时请求隐藏观察；GUI 打开时释放实际所有权。门禁只在输入状态变化时转换，重复存档快照不会取消移动或发出锁定申请。关闭背包时先恢复 world input，再请求 Pointer Lock，避免成功事件被尚未恢复的输入门禁拒绝。申请被浏览器的用户激活/权限规则拒绝时，仍保留隐藏观察意图，下一次真实点击能够继续申请；首次无激活的预期拒绝不报红色故障。失焦、隐藏、离页和销毁仍使迟到锁定失效。

ResizeObserver 只记录待用 CSS 尺寸及 DPR，在同一 RAF 内先应用尺寸再绘制完整世界，避免画布清空后跨帧等候。相同 backing size 与 DPR 不写 canvas.width/height。updateGate 只在真实效果变更时清除菜单合成标记，不随存档反复拆除已合成的画面。

Ctrl + W 在世界输入时的页面 keydown 走 capture preventDefault；输入框及 GUI 不拦截。浏览器保留的关闭标签页动作不能仅靠普通页面 keydown 可靠阻止。依据 [Chrome Keyboard Lock 官方说明](https://developer.chrome.com/docs/capabilities/web-apis/keyboard-lock)，新增暂停菜单独立全宽“全屏游戏”入口，使用网页 API 全屏后仅锁 KeyW（含 Ctrl 组合），不锁 Escape。离开全屏、GUI、失焦、隐藏、离页、销毁释放键盘锁。普通窗口保持原版双击 W 疾跑；不强制全屏、不使用离页确认框冒充快捷键拦截。此按钮为满足当前避免 Ctrl + W 误关的工程决定，保留前两行暂停菜单顺序。

## 验证

- 类型检查、完整规则测试、root/Pages 普通构建资源审计与双路径 HTTP 检查；输入规则覆盖默认恢复、重复门禁、迟到申请、普通/Ctrl 右键不释放、UI 快捷键独立、KeyW API 捕获与生命周期、相同尺寸不清空。
- 独立 Chromium 原生输入通过：进入后真实左键满足首次用户激活；Ctrl + 右键不释放；E 打开背包后释放；背包内 Ctrl + 右键不锁定；Esc 关闭背包后无需额外点击实际恢复锁定；暂停菜单全屏按钮同时进入 API 全屏与隐藏观察；Keyboard Lock 的 KeyW 请求实际成功，Ctrl + W 原生浏览器事件 defaultPrevented=true。
- 连续至少四次提交后观察 95 个新绘制的默认 framebuffer 样本，没有黑色样本，观察窗口内没有无尺寸变化的画布重设。此为指定像素采样与 setter 诊断，不是对所有浏览器/GPU、所有屏幕像素无闪烁的证明；本次未对实体桌面或真实 OS 保留快捷键注入作结论。
- 八条作者消息仍按约 3 秒首条、其后约 5 秒分条，末条导航文案正确；发送普通聊天后也会恢复观察。导航离开释放鼠标，未出现应用 pageerror。
- 首次直接打开新文档的 Pointer Lock 受浏览器交互权限约束，可能仍须点击一次画面；不能以 CSS 隐藏光标代替实际锁定。普通窗口模式保留键的限制在教程中明确，不以 CDP 键盘事件冒充操作系统 Ctrl + W 已被强行覆盖。
