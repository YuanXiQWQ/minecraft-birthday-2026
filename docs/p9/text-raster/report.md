# 全界面文字最终像素清晰度

用户指出语言页只是示例，多处文字仍模糊。此次修正共用文字与GUI像素链，不更换字体、不加粗或提高文字颜色来掩盖采样问题。

## 已复现的原因

691×800 CSS视口、DPR1.25下，语言括注应显示为864×24物理像素，但测量误差使密度成为2.000000035，`Math.ceil`把画布建为865×25。浏览器把它压回864×24，产生中间灰色像素。此前的检查只核对宽度近似比例，漏掉高度和最终合成。原字形画布自身仍是不透明灰色及阴影，模糊发生在到屏幕的采样阶段。

[原始用户截图](evidence/user-reported.png)未经编辑；[修正前测量](evidence/baseline.json)记录实际尺寸，不把截图重采样当作修复。

另一个共用问题是菜单平面使用`transform: scale`，部分控件即使边界尺寸表面为1:1，也会经过中间层采样。菜单直接按最终CSS尺寸放置控件，不使用整页transform或zoom；保留原版逻辑坐标，控件绘制与输入坐标共用原版GUI比例。文字画布使用实际物理像素尺寸，保留浏览器原生栅格定位、已有居中和Toast动画的CSS变换。

## 修改范围

- 共用`rasterSize`使用最近整数，避免误差额外增加一行/列；`alignRaster`同时核对宽、高和较大原点偏移，物理分辨率画布保持1:1输出。采用`crisp-edges`最近邻采样；1/8物理像素内保留浏览器原生栅格定位，避免微小translate使滚动层、居中容器进入不同采样相位。该阈值为工程选择，以实际截图像素比较核对。
- PixelUI段落、菜单、按钮、输入框和音量滑条统一处理；聊天画布直接使用实际视口像素尺寸，取消逻辑视口取整后再放大的过量像素。
- 背包/配方/进度的共享GUI画布、Tooltip及Toast统一对齐，保留原版位图/Unihex字形、0.5像素Unicode阴影、颜色和NEAREST。
- 不更改存档版本、数量、输入事务或游戏活动时钟。其他工作区场景与文案草稿不属于本次修改。

## 验证方法

除了规则和构建回归，正式Chromium脚本增加`--text-raster`：每种DPR使用独立Chromium进程，覆盖100%、125%、150%、200%及root/Pages路径，对主页标题/正文、菜单括注、语言行、按钮、Tooltip、背包标题、配方搜索、打开的聊天、滑条文字逐项比较。

检查直接读取源画布的不透明字形像素，再读取浏览器真实PNG截图中对应屏幕像素，要求色差不超过1，记录不匹配数量。滚动层最终栅格原点可能与DOM边界四舍五入相差1个物理像素，因此允许整体±1像素整数平移；不允许缩放、插值、逐字或逐像素寻找匹配，并记录平移量及未平移的差异。不以`imageSmoothingEnabled=false`或DOM边界比例代替最终像素检查。测试选择实际可见的文字，避免把生日重播控件遮挡或窄屏隐藏面板当作模糊。结果见[evidence/raster-checks.json](evidence/raster-checks.json)；完整保存、刷新、跨标签及旧缓存回归见[evidence/browser-results.json](evidence/browser-results.json)。所有截图均为真实页面，未编辑。

实体电脑和用户实际浏览器缩放仍由用户体验核对，本次没有操作用户桌面。CI、部署和线上build在提交推送后分别核对。

## 本地结果

四种DPR的40项实际截图比较全部通过，共418,299个不透明字形像素，匹配后的最大RGB差为0。root/Pages正式页面、语言保存、刷新、跨标签、库存/生日事实、旧缓存更新、窄屏重置和写入失败回退通过。当前工作区全套730项规则测试通过，相关定向回归42项通过；TypeScript、双路径构建审计及HTTP资源检查通过。工作区包含其他同时进行的场景修改，发布时仅提交本文列出的UI绘制文件与证据，以提交版本的CI和线上核对作为发布确认。
