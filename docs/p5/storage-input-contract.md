# P5 稳定布局与输入事务合同

本合同扩展[P3](../p3/storage-contract.md)的稳定载体；D07完整方案已由用户明确回复“接受该D07完整方案”。当前个人GUI落实情况见[D07交付](d07-review.md)，历史报告保留当时批准状态。

- 信封：format1，contentVersion=p5-layout-1，vanillaVersion26.3；同一SAVE_KEY/LOCK_NAME、generation和revision协议。
- player.version1/data：selected0–8、hotbar固定9组、equipment精确head/chest/legs/feet/offhand、presets固定9个null或9组数组。每个非空组是{id,count,components?}，必须已永久解锁且符合原版上限/装备组件。原版数量/槽位规则来自`app/web/src/data/inventory-rules.json`，由工具从已校验P4规则投影，测试逐项比较113条。
- components只接纳已处理的damage、custom_data JSON；未知容量/装备等覆盖拒绝。JSON身份忽略键序，原版默认damage0归一，非同组件不得合并；不模拟耐久磨损。
- cursor不写入该稳定布局。个人2×2、站点内部内容的退出/刷新规则按下方已批准D07合同；当前未实现这些P6菜单/内容。未来非空字段需要明确版本迁移，不能塞进Reserved.data。
- 稳定槽变更必须发送`inventory`命令：intent、cursor、expectedLayout；光标是本页输入载体，结果从成功事务返回，不广播为他页光标。expect不是全存档快照，必须在独占锁内与最新稳定布局比对。它用于拒绝同槽竞争；并不是用revision冒充原子锁。
- 一次完整拖动是一个命令，移动时只收集唯一合法目标，不改组；释放时计算分配。合法性在提交时再检查。source复制、creative中拖/预设加载和drop是显式非守恒操作；普通取放/转移/交换按身份守恒。
- UI乐观显示本页有序命令，但只把最后成功的cursor作为已提交运行态。锁内拒绝/写失败会撤掉未提交投影；后续队列失效。generation变化及卸载也使队列失效；无pagehide快照回写。
- P3 migration仅从校验通过、player精确version0/data:null的旧内容转换；复制其他持久事实，原档保留到实际变更写成功。未来/损坏/未支持字段继续保留原字节并只读。
- reset使用原有完整确认token，清全部进度载体/预设，保留设置；同锁内旧epoch命令拒绝。页面恢复先读最新再写，不接受旧快照复活。

## D07：已批准的退出与实例内容合同

1. 关闭个人背包或个人2×2界面：取消未提交拖动，清空光标与个人合成填充；不生成掉落、不返还到有限背包、不撤销解锁。当前Items/Equipment属于同一个人菜单，切页不等于关闭；E、Esc、Done关闭执行清光标。
2. 九格、选中格、装备、副手与C/X预设持久保存。刷新、返回页面和跨标签恢复稳定布局；重置按D09清进度、保留设置。
3. 工作站输入/燃料/输出及漏斗内部组按稳定实例保存；关GUI、切场景不清空，刷新恢复。加工/离线计时D08仍另审。当前contents仍为version0空保留位，P6接入时定义并验证新内容版本。
4. 拆除工作站删除该实例与内部临时组，不返还到有限背包、不撤销解锁、不隐式授予未领输出。输出取得由D05另定。当前没有正式拆除/加工内容业务，不能用P5清光标测试声称这一项已实施。
5. 刷新/重新进入时光标和个人合成格为空。仅失焦/PointerCancel取消未提交手势，保留已提交槽位与当前光标；Esc关闭按第1项清理。页面pagehide清光标并使旧队列失效，实际BFCache命中仍待环境测试。普通blur不等于pagehide。
6. 稳定变更通过版本化命令和共享锁协调，不上传旧快照。PersonalCursor使用独立epoch拒绝关闭前异步命令返回的cursor；已经提交的稳定槽操作仍完成，不以关GUI回滚持久事务。新开界面后的有效命令可产生新光标。

这与Java个人菜单返还/掉出临时物品存在明确差异，利用永久无限目录避免新增有限库存；这是用户已批准的项目适配，不是已通过Java客户端实测的声明。关闭后的cursor清理无需新增存档版本；稳定布局格式和P3迁移保持不变。

当前强制互斥覆盖协作应用页面；不能抵御不遵守协议的同源脚本或用户手改localStorage。D05/D06/D08业务没有在D07批准中隐式决定。
