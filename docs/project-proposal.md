## 2. 网站结构

### 展示主页

- 独立的 index 展示页：生日标题、故事文案、邀请按钮、初始空桌子。
- 点击按钮后才进入交互游戏；主页不承担全部游戏逻辑。
- 在游戏里将蛋糕放上桌后，主页桌子也应显示蛋糕，并通过存档保留该结果。
- 主页桌面为实时三维模型与原版素材，不以二维截图/CSS伪三维替代；英文初稿从外部本地化文件读取，示例故事不是定稿。P3用仅测试环境的命令夹具验证完成投影，不提前制作最终流程。

### 交互游戏

使用作者预先设计的四个真正三维场景，通过三维场景对象点击获取资源。固定指内容与可操作范围有界，不生成开放世界、不允许玩家自由移动；不限制为二维。场景必须具备三维方块模型、空间坐标、透视、深度及遮挡。四场景采用位于场景内部、接近玩家眼睛高度的第一人称观察视角，禁止将空中俯视建造平台作为最终表现。场景占据浏览器主要可视区域，主要内容在页面中央构图，无屏幕中央准星或瞄准标记。继续以自由鼠标指针点击真实模型并经摄像机射线拾取，居中构图不等于强制中心射线。固定或受控观察均须保持第一人称；用户已选择无背包/GUI时右键拖动原地转向、短击右键交互，拖动不能同时打开设备；阈值/角度与四场景可操作范围仍待审，不强制 Pointer Lock，不加入 WASD 行走或飞行。实验工具默认隐藏在可收起开发面板中。不得以单张背景截图、预渲染场景图片、二维图层或 CSS 伪透视替代。具体场景布局和摄像机控制范围尚未定稿：

| 场景 | 核心内容 |
| --- | --- |
| 平原 | 树木、草及相应自然资源 |
| 农场/农田 | 预先耕好的土地、种植小麦、鸡、牛和鸡旁的蛋；甘蔗的具体布局待设计 |
| 矿洞 | 石头、铁矿、煤矿及工具等级判断 |
| 家 | 桌子和蛋糕最终放置位置 |

场景可以拥有独立视图，不要求每个场景都对应独立 HTML 文件。主页与游戏的具体路径由实现方案确定；静态托管应支持直接访问，并正确处理 GitHub Pages 仓库子路径。

## 3. 物品与进度模型

- 所有物品的核心状态只有“未获取”和“已获取”，即解锁状态。
- 解锁一种物品后可无限使用。将同一材料放入多个配方格不会消耗库存，合成、使用与熔炼不建立资源数量门槛。
- 工具不消耗耐久。
- 物品栏作为类似创造模式的已解锁物品来源；拿到快捷栏不会减少来源物品。
- 快捷栏允许重复物品和原版堆叠上限。堆叠数量用于交互，不作为资源经济系统。
- 快捷栏、选中格、装备/副手与九组C/X工具栏预设接入版本化本地存档。D07已批准：关闭个人菜单清光标与个人合成填充，刷新/重入为空；失焦/PointerCancel只取消未提交拖动；设备内容按实例保存、拆除清该实例内部组，不返还/掉落或隐式解锁。详见[P5合同](p5/storage-input-contract.md)的完整边界及实际实现范围，D05/D06/D08不随之批准。

| 熔炉 | 圆石、工作台 |
| 铁资源 | 石镐或更高等级合适镐采集铁矿；矿物掉落名称按目标版本核实 |

## 4. 配方、熔炼与功能边界

- 页面中实际可获取元素及其派生产物应支持可达的原版配方，不能仅因物品不在蛋糕主线清单就拒绝正确配方。
- 无来源、不可达的材料不要求专门添加配方；例如场景没有钻石，不需要单独实现钻石镐。
- 支持原版适用燃料，包括木棍、木制工具等；支持原木烧成木炭、金属装备熔炼回收等可达规则。
- 高炉能够直接推进铁锭主线，应支持其放置和功能；与熔炉的适用原料和速度差异应符合目标版本。
- 配方可制作与方块可放置、方块功能可交互是不同边界。武器和盔甲可作为副产物装备，但没有战斗或属性收益。
- 装饰元素不自动成为可采集资源。例如可以展示草方块而不允许采集泥土，以控制可达物品范围。
- 原版配方书承担配方查询职责，使用原版风格的物品提示和解锁配方通知。

### 功能方块的最短依赖规则

| 类别 | 用户规定的范围 |
| --- | --- |
| 直接生产主线材料 | 允许，例如工作台、熔炉、高炉 |
| 一层简单辅助 | 方案 B 已正式采用，包含漏斗的放置、朝向、容器交互及辅助炉的数据传输；精确行为依同版证据与批准适配落实 |
| 更远的辅助链 | 不允许放置，例如箱子→漏斗→熔炉，或拉杆→漏斗→熔炉 |
| 与主线及简单辅助无关 | 不增加功能，例如切石机 |

按最短有效功能链判断，不人为拉长依赖。用户已明确排除箱子、拉杆、压力板的放置功能；即使这些物品可以合成，也不因此引入仓储或红石系统。

## 5. 方块放置与防止卡关

**用户正式采用 B：自由放置发生在真实三维场景内。** 在各场景设计允许的三维区域选择合法位置，放置、调整朝向、交互和拆除工作台、熔炉、高炉及漏斗。区域形状、容量、可用高度和摄像机由后续场景设计确定，不以 P1 的 7×5×2 夹具为正式限制。

- 在有需求的场景（包括平原、矿洞）保留可用建造区域和必要工作站空间；不再以作者指定工作站槽位代替 B。
- 最终蛋糕始终在家的桌子上放置。
- 放置不能堵死尚未解锁的主线资源来源，或使必要来源/设备在允许视角下永久无法选择；补货不能覆盖已放设备。
- 铁资源至少保留可达来源，覆盖徒手破坏铁矿却没有取得掉落的情况。
- 燃料可达性综合判断煤炭、原木等替代路径，不能因某一种燃料被挡就过度限制，也不能挡住全部剩余途径。

此前“先比成本再选 A/B”的决策流程已经结束。P1 实验的有限坐标、实例、朝向、端口、传输、存档及样本保护可作为后续规则设计依据；其二维诊断界面不复用为游戏场景，也没有验证真实 3D 渲染可行性。

## 6. 场景补货与种植

- 离开场景再返回时，自然资源自动补货，包括矿石、石头、树木资源和鸡蛋。
- 补货不等于场景重置：保留玩家放置的方块、种植的小麦及其他持久变化。
- 小麦使用固定、很短的阶段时间，无需完整随机刻模拟。
- 农场提供已有耕地，鸡旁固定生成蛋，不额外加入喂鸡或锄地解锁门槛。

## 7. UI、输入与原版体验

- 3D 场景与屏幕二维 GUI 明确分离：背包、工作台、熔炉、高炉、漏斗、配方书和设置继续使用原版风格二维界面，不将容器操作搬成三维空间面板。
- 优先使用原版背包、背包合成格、工作台、熔炉、设置、按钮、文本及提示 UI；只有确无对应元素时才制作符合 Minecraft 材质风格的补充。
- 物品、方块、UI 材质、粒子素材使用原版内容，不用自行绘制的替代素材。
- 主线物品占据固定、按建议流程排列的位置；未解锁以黑色蒙版表示，解锁后点亮。
- 非主线物品按获得顺序添加。鼠标悬浮在已解锁和未解锁物品上均显示原版风格物品信息。
- 玩家可以打开背包查看进度，使用原版配方书。
- 核对并实现与本项目 UI 重合的 Java 版默认操作：左右键取放、半组/整组、均分、选择物品、拖动复制、整组复制、数字键换到快捷栏、Shift 自动转移至适用槽位等。
- 未装备时手持盔甲右键装备；无效槽位不接受不适用物品。
- 快捷键以核对后的目标版本为准，不把会话中举例的清单误当作全部输入需求。浏览器默认行为冲突及触控适配需在实现设计中处理。

## 8. 蛋糕与生日庆典

- 庆典触发点是把蛋糕放到家中的桌上，不是仅合成出蛋糕。
- 使用覆盖整个页面的演出，优先安排开发和效果验证。
- 烟花需符合原版系统：小型球状、大型球状、星形、苦力怕形、喷发状，并支持闪烁、踪迹附加效果及原版音效。
- 配合原版成就/进度达成音乐、经验声音，可加入页面闪光、音乐及祝福文字。
- 使用原版粒子与相关机制作为参考，不为庆典引入完整世界模拟。
- 游戏完成结果同步到主页桌子并持久保存。刷新后是否重播、是否提供手动重播以及演出时长尚待明确。

## 9. 存档与设置

用户明确不使用账号、数据库或服务端存档，要求设置中提供重置存档按钮，方便重复游玩。

用户已明确：重置仅清除本项目进度并恢复空桌，保留语言和音量；静音随音频设置保留。P3实现二次确认、版本/校验、Web Locks逐事务协调和重置代次，错误原档保持只读；备份/损坏恢复产品流程、离线计时仍待设计。详见[存档契约](p3/storage-contract.md)。

## 10. 技术与素材基线

- 用户指定 Minecraft Java 版，不采用基岩版，并在会话中指定 26.3 为目标。此处记录目标要求，不代表已独立确认该版本的发布状态；实施前须核实准确版本及对应数据。
- 参考源码仅用于范围内的原版行为，如声音触发与烟花粒子，不引入移动、世界生成等系统。
- 用户倾向社区映射；若参考映射源码，先选定同版本的一套映射，不混用官方和社区方法名。
- 用户说明项目为非商用生日礼物、仓库不公开；实际仓库及 Pages 的访问范围不在本次操作中更改。
- 原版资源在引入时记录版本、来源与依赖哈希，并正常纳入Git及普通构建；未来公开发布的适用条款与部署条件另行核对，不阻碍开发期使用。
- 用户授权 P2 首轮以 TypeScript/Vite 和优先 Three.js + WebGL2 验证，精确实验版本见 P2 报告；不等于批准 React、动画/音频库或完整应用工程。
- 浏览器真实 3D 渲染是强制需求；Three.js/WebGL2 的本轮可行性证据不替代原版资产、完整 P2 或目标设备验收，无需实现完整 Minecraft 世界引擎。
- 原始会话是开发背景资料，不作为网页内容或公开资源发布。

## 11. 开发前需收敛的事项

1. 核实目标 Java 版本，选择一致的配方、标签、熔炼、燃料、堆叠、UI、声音、粒子和映射数据来源。
2. B 和真正 3D 已确定；后续 P2 必须验证原版模型、三维点击、放置预览、遮挡、朝向、漏斗邻接及基本性能，不重新将 A/B 作为待选产品方向。
3. 列出场景可获取元素，计算可达配方范围，并区分可制作、可装备、可放置及可执行功能。
4. 确定前端技术栈、静态路由和 GitHub Pages 子路径方案。
5. 确定本地存档结构、种植离线时间策略、重置行为和庆典重播规则。
6. 定稿英文文案、场景布局、主要设备范围及浏览器输入适配。

## 12. 验收方向

- 从全新存档出发，可以依照原版最低采集条件完成材料解锁、合成蛋糕、放到桌上并触发庆典。
- 同一种已解锁材料可填入多个配方格；合成、熔炼与工具使用不会消耗实际库存或耐久。
- 可达的非主线配方、合法燃料、适用熔炼回收规则按目标版本生效；不扩展到无关游戏系统。
- 主线固定物品位置、未解锁蒙版、悬浮信息、配方书、重复快捷栏物品及相关快捷键符合约定。
- 切换场景能补货，同时保留放置与种植；选定放置方案不会导致主线卡死。
- 四场景均为实时真正 3D；合法三维区域内 B 的放置、朝向、交互、拆除及漏斗数据流有效，窗口/摄像机变化不改变逻辑位置，不可穿透遮挡误操作。
- 主页起始为空桌子；完成游戏后返回主页及刷新均能看到蛋糕；重置恢复初始状态。
- 正式文本来自本地化资源，初始展示英文；静态部署下入口、子路径和资源加载有效。
