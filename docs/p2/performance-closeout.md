# P2 收尾性能分析

2026-10-21。这是四轮原型后的集中收尾，不是新的P2研究轮。原始第四轮记录不改写。全部时间单位为ms；测量门槛不是用户批准的产品预算。

## 旧长帧与归因边界

第四轮 `evidence/celebration-round4/1440-joint-final.json` 的54.2、91.8间隔出现在相同模拟时刻约4.102秒、6752存活/3449可见粒子附近；1280对应记录没有超过33.3ms的间隔。旧记录没有分项CPU或GPU计时，无法证明是GC、截图、自动化、应用计算或GPU导致，不能补造归因。

收尾采用同一2632026种子、五形状组合、Trail/Twinkle、原版模型/粒子/声音和打开的原版背包GUI。正式连续区间内不截图、不改窗口、不重建、不编译、不操作调试菜单。两个完整组合预热（约12.4秒）后，连续十个完整组合（约62.05秒）。原版资源已自动从仓库加载；没有调试几何替代。

环境：Windows，Chromium155，ANGLE/D3D11，RTX3080Ti Laptop，20逻辑线程；1440×900，DPR/渲染DPR约1。该高端设备/单浏览器结果不能作为低端设备或全产品性能验收。RAF观测约240Hz，不等于显示器最终呈现帧率。

## 分项测量

`FrameProfile`在现有单一RAF内分别测量固定tick模拟、可见粒子筛选/插值、深度排序、顶点属性更新、音频逐帧工作、CPU渲染提交、诊断序列化和DOM写入。批量声音调度在每轮开始另记`schedulingMs`，不会因帧内audioSchedule为0而被遗漏。

GPU使用实际 `EXT_disjoint_timer_query_webgl2` 异步查询，每30次提交采样一次，过滤disjoint结果，不调用gl.finish。GPU耗时不等于CPU的renderer.render调用耗时；异步结果到达帧不等于产生结果的帧。Long Task API和前一回调耗时、RAF调度延迟保留在原始记录中；没有GC专用trace，不能从空白区间推断GC。

## 稳定性与诊断干扰

真实WebGL丢失/恢复测试在同一canvas收到trusted lost/restored事件，恢复后glError=0、单一适配器和单一待执行RAF，领域布局不变，GUI关闭。声音和模拟时钟暂停，显式Resume后自然结束。强制丢失区间中的帧间隔不能纳入正常连续性能样本；`context-resumed-run.json`保留该异常路径的158.3ms间隔，不隐去失败/异常数据。

原始帧数组导出后曾出现两次浏览器控制超时，记录见`diagnostic-timeouts.json`。将大段原始导出保持为隐藏诊断DOM后，核心检查可连续操作；这只减少诊断页面布局工作，不能证明第四轮的旧暂停也是同一原因。正常采样期间只显示限量摘要，完整帧数组在采样结束后导出。

## 建议预算与缺失数据

建议与用户讨论60Hz目标：热态联合负载P95不超过16.7ms、P99不超过33.3ms；>50ms单独逐次审查，并给加载、失焦、恢复等异常路径单独报告。建议先将本切片约180 draw calls、9000存活粒子作为可复现基准，不能把它们当四场景容量上限或擅自删减功能的理由。以上尚未获用户批准。

仍缺目标低端GPU、Firefox/WebKit、真实DPR2、长期热降频/电池模式、四正式场景最密布局和最终庆典演出负载。P7/P8集成与P9候选需在确定目标设备及预算后复验；目前仅支持P3模块化与接口工作的工程判断，不支持正式全产品性能通过。
