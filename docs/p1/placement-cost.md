# P1：A/B 放置方案完整增量评估

日期：2026-10-20。结论状态：成本分析与推荐供审核，**没有选择 A/B，没有批准或排除漏斗功能**。本轮没有实现放置/漏斗/软锁原型，没有实测开发工时。证据等级见 [数据核实](vanilla-data.md#1-证据等级)。

## 1. 公平比较的共同边界

两方案都保留四个固定场景、工作台/熔炉/高炉、原版容器操作、无资源消耗、种植与自然补货、存档、固定家中蛋糕桌面。不能把 A 的拆换/保存成本算成零，也不能让 B 背负完整世界生成、玩家移动、战斗、区块或红石模拟。

- **A：引导槽位**。作者配置合法位置与类型；允许放置、打开、拆除和替换；需要工作站的场景有入口，熔炉/高炉可共槽。按当前待审范围不启用辅助方块；这不是声称固定坐标在技术上绝不能接漏斗。
- **B：有限网格自由放置**。在预先设计的画面/放置区域中离散放置获准的功能方块，支持同类实例和朝向；如批准低成本自由交互，则按用户条件支持一层辅助漏斗。箱子、拉杆、压力板仍不放置。

B 不能只做平面格子后承诺原版漏斗所有端口：顶部供料、侧面燃料、下方抽取涉及上下关系。可采用有界的逻辑 x/y/z 单元投影到固定画面，或足以表达这些关系的分层剖面；它仍不需要完整体素引擎。具体区域、层数、朝向操作与视图是待审设计，不在本轮定死。

## 2. 原版漏斗相关静态证据

同版本 HopperBlockEntity、HopperBlock、AbstractFurnaceBlockEntity 的静态读取（S）：

- 漏斗有5个物品槽；朝向参与目标位置选择，不能只按图标碰到炉子判断连接。
- 成功搬运后存在8 tick冷却；相邻漏斗还存在时间协调分支，不能把全系统统一成每帧转移。
- 转移检查源可取与目标可放，并受具体方向约束；满目标、空源、失败转移需保留组。
- 炉上方访问输入槽0，侧面访问燃料槽1，下方访问输出槽2及受限的槽1；底部可抽的燃料余留物由标签决定。
- 输入槽“允许放入”和“能加工”分开。顶面塞入不可加工物可阻塞；侧面不能把粗铁当燃料。
- 漏斗本身包含世界掉落实体吸取路径。项目没有世界掉落实体来源，不能因此新增 ItemEntity 物理系统；是否对现有直接采集流程有对应吸取对象，应另行说明。暂无对应对象时标不适用，不伪造掉落系统。

这些是静态行为边界；真实相邻漏斗的 tick 先后、朝向交互、完整槽路由、GUI 布局仍需客户端验证。B 若启用漏斗，不可只完成“给炉输入加一个按钮”。

## 3. 工作分解与相对成本计算

单位为**相对分析点**，1点表示一个小而可独立验证的工作包，仅为比较口径，不等于一天、一百行代码或已测生产率。估算包含规则、状态、UI 适配与对应验证；不包含两方案共用的配方引擎、完整 GUI 基础、四场景绘画、资产取得和庆典工作。

| 工作包 | A 估算点 | B 估算点 | B−A | 增量依据 |
| --- | ---: | ---: | ---: | --- |
| 坐标、布局、命中与遮挡 | 2 | 4 | 2 | A 固定作者位置；B 任意格占用、重叠选择/多层显示 |
| 放置、拆换与实例生命周期 | 2 | 3 | 1 | A 也要安全关闭GUI/保存/替换；B 多实例与动态合法位置 |
| 朝向和连接拓扑 | 0 | 3 | 3 | B 有端口朝向、邻接更新、拆除后的失效连接 |
| 共用工作站 GUI 接入 | 2 | 2 | 0 | 两者都付出；不能把已有熔炉GUI重复记作B新增 |
| 漏斗5槽 GUI 与输入矩阵 | 0 | 2 | 2 | 新容器外观/槽接受/Shift/数字键/光标行为 |
| 漏斗推送、抽取、面规则、冷却/顺序 | 0 | 5 | 5 | 双向协议、阻塞、链和环、有界调度、余留物 |
| 自然补货与放置冲突 | 1 | 3 | 2 | A 空间分离；B 定义占用后资源重生、遮挡与保留行为 |
| 防软锁与替代来源 | 1 | 4 | 3 | A 作者布局不变量；B 对假设占用后的能力/替代燃料检查 |
| 持久化、迁移和重载一致性 | 2 | 4 | 2 | A 保存少量槽和实例；B 单元/方向/连接重建/传输计时 |
| 无限物品适配和产物取得归属 | 1 | 3 | 2 | B 增加临时搬运、无限输入、自动领取与满槽的组合 |
| 自动化反例和状态覆盖 | 2 | 5 | 3 | B 需要端口、连接顺序、环、全资源占用和刷新交错测试 |
| 手工场景/缩放/可理解性验证 | 1 | 3 | 2 | B 的放置/旋转/拆除命中及设备遮挡操作更复杂 |
| **合计** | **14** | **41** | **27** | B约为A的2.93倍，仅此子系统范围 |

A 的2分 GUI接入仅指已有工作站与放置实例的连接，不是整个背包/工作站GUI实现。B 的自动化预算不替代 P5/P6 已有 GUI 基础测试，只计算因动态布局与漏斗新增的组合。

### 3.1 不确定性与敏感性

工作包规模未经原型校准，不能将41点冒充实测。若输入/槽位/时钟协议复用顺利，B各包合计可约29点；若多层命中、相邻传输顺序和软锁组合需反复调整，可约54点。A 对应保守范围约10–22点。范围是工程估计，不是统计置信区间，也不能简单相减得“保证最少7点”。

即使网格占用与朝向完全复用，B仍需5槽漏斗容器、合法端口传输、无限适配和新增验证；因此不能仅因“格子放置代码很少”声称B低成本。反过来，不应因为这些新规则存在就断言必须做完整世界：N个有限单元、H个漏斗，每调度步只检查有限邻居与5槽，复杂度随H/连接数有界；不需要全世界寻路或区块 tick。

当前证据支持“B有显著额外工作面”，尚不足以证明实际工时一定超过用户可接受预算。最有价值的校准是隔离验证一个完整漏斗→炉及炉→漏斗往返链路、换向/拆除/满槽/读档，而非仅拖动方块的漂亮演示。

## 4. B 的完整状态和算法边界

以下是设计候选，不是已写应用代码：

| 领域 | A 需要 | B 完整新增 |
| --- | --- | --- |
| 实例身份 | slotId 与 stationId分离，类型切换新实例 | 稳定实例ID、逻辑cell、朝向；禁止按屏幕坐标保存 |
| 连接 | 无动态传输网络 | 根据相邻单元/目标面重建有向连接；拆目标即时失效，不存易过期的对象引用 |
| 内容 | 炉输入/燃料/输出与计时 | 漏斗5槽、冷却/调度顺序、传输中的原子性；不能存半次搬运 |
| 转移 | 用户命令与设备加工 | 先模拟目标容量/权限，再一次性从临时源扣1并写目标；失败全不变，U不减 |
| 无限适配 | 炉保留输入引用与输出上限已待批 | 不能令每个传输源天然无限；区分设备加工“不消耗”与临时容器搬运“移动” |
| 连接链/环 | 不适用 | 同类漏斗邻接是否开放需定案；若开放，以tick快照/顺序与冷却限界，不按“循环到稳定”反复运送 |
| 持久化 | 作者槽状态、实例内容 | cell/方向/冷却与明确恢复时钟；先建所有实例再重建连接，校验非法面和越界 |
| 场景补货 | 自然模板与持久槽空间分离 | 自然节点被占时不可覆盖玩家实例；资源重生策略及遮挡恢复需合同 |
| 交互 | 引导框、拆换、打开 | 放置预览、方向选择、非法反馈、重叠命中与可撤回操作；无玩家移动 |

漏斗能直接辅助炉，因此方块类别符合用户的一层辅助条件；不应人为把它先接箱子/拉杆，再以链变长为由排除。箱子虽可制漏斗但不可放置；不引入独立仓储、红石断电、压力板或战斗。

多个漏斗是否可串联不能仅按某次玩家摆出的长链误判该类型不符合最短功能链；应根据最终获准的交互范围定义，同时把必要的同类相邻/环测试计入预算，不能以“只考虑一只漏斗”估算无限布局。

## 5. 自然补货、防软锁和持久化反例

书面案例，无原型/游戏执行记录：

| 案例 | A | B 必须处理 |
| --- | --- | --- |
| 错误工具挖完铁矿但未取得粗铁 | 不撤销解锁；切场景自然矿补货 | 若试图占住最后铁来源且粗铁/铁锭未解锁，放置前拒绝；不能用“可拆回来”绕过用户保护 |
| 煤矿被占，但已解锁原木/木板 | 资源槽隔离，通常无冲突 | 燃料仍无限可达，不能只因煤矿全挡就拒绝所有放置 |
| 未有任何燃料解锁，煤来源被挡，最后木来源又拟被挡 | A 布局保证来源不被设备占用 | 对假设后的来源/能力综合检查并拒绝；不只检查当前快捷栏是否有煤 |
| 出入场景时资源复生在炉子后/同单元 | 作者布局应避免 | 不覆盖炉、作物；自然层占用、视觉遮挡与可点击性需一致 |
| 网格全放满设备，主线工作台/农田无位置 | 有预留功能槽与耕地 | 资源还在不代表主线可完成；保护必要种植/放置能力与最终桌面 |
| 炉旁漏斗移走、目标瞬时拆掉 | 不存在动态传输 | 传输先后原子化；失败归还原临时源，不丢组、不越权解锁 |
| 输出满但燃料无限 | 炉有界输出，等待领取 | 加工/推送/抽取都检查容量，不能无限堆计数或死循环 |
| 重载发生在成功转移和领取通知之间 | 单命令保存/事件边界 | 存档只含完整状态，恢复不重放取得通知；自动产物解锁归属先经批准 |

B 的保护可在有限能力/资源图上计算，不实现完整配方引擎于 P1。未来 P4 有闭包证据后可复用；P2 若仅做小样本验证，必须说明只证明该样本，不能宣称全项目已无软锁。

## 6. 推荐与用户选项

**当前推荐**：以A作为预算和风险基线，同时保留B为待审选项；理由是完整增量集中在真实传输和状态交互，尚无证据证明它只需极少额外工作。这不是正式选择，不改变 D03 的“未定”，不将漏斗提前标为排除。

| 用户候选 | 收益 | 取舍/所需后续证据 |
| --- | --- | --- |
| 选择A，可拆换引导槽位 | 风险较低，仍保留设备放置和原版GUI | 较少布局自由；按用户条件不启用辅助功能，需明确确认该取舍 |
| 选择B，接受完整增量 | 满足更自然的有限布局和一层辅助体验 | 需要漏斗/朝向/传输/GUI/保护/存档全套预算，不承诺仅多网格代码 |
| 先授权隔离B技术验证，再决定 | 用真实复用效果替代估计，符合用户“成本低则开放”的原则 | 增加一次可独立审查实验；须限定不开始正式游戏、无世界模拟；本轮未做 |

若用户仍倾向B，推荐先采用第三项获取校准证据，而不是仅依据27点估计否定。接受放置结论与接受临时容器/自动产物取得语义是不同决定，不能一次“选B”就默认所有适配已批准。
