## 2. 对照设置与语义合同

共同部分为实例 ID、槽位权限、原子命令、同一熔炉/高炉加工函数、永久解锁、临时组、补货、存档和同一个诊断 Inspector。A 使用类型限定的三个作者位置；B 使用 70 格、两个深度层、多个设备、水平朝向/向下漏斗出口。工作台只是九槽容器占位，未实现配方。

没有用“B 拖动方块成功”代替漏斗验证。B 默认链包括上方粗铁→炉输入、侧面木棍→燃料、炉下方漏斗抽出→旁边收集漏斗；同样运行炉与高炉两种设备。AB01 另以完全相同的输入内容比较 A/B 的机器逐步结果，避免把不同预置数量或供料延迟当成实现差异。

实验使用 [GUI E05–E07 等推荐候选](gui-behavior.md)，不是正式产品决定：

| 操作                     | 实际实验状态转换                                         |
|--------------------------|----------------------------------------------------------|
| 从目录复制木棍×3         | U(木棍)保持；光标=3；没有永久数量字段                    |
| 漏斗木棍3→炉燃料0        | 源2、目标1、U不减；失败则两个载体不变                    |
| 炉加工/续燃              | F0/F1 保留引用及临时显示数；周期产出有限 F2，满则暂停    |

| 新铁锭自动抽到合法目的地 | F2减1、目的+1，首次加入U；下游满不加入U                  |
| 拆除/替换                | 删除旧ID/内容/计时，新实例干净；不撤销U                  |
| 保存、刷新、恢复         | 设备内容/方向/计时保留，光标和瞬时事件清除；连接重新派生 |

快速路由按钮验证输入优先和容量规则；没有验证真实 Shift 按键、批量结果、拖动、装备或创造目录全部分支。剩余物仅预置桶抽取权限，不生成蛋糕三桶；不得宣称 GUI G01–G30 或完整剩余物语义通过。

## 6. 推荐、约束及仍未验证事项

**推荐 B 的理由**：用户需要的自由布局收益可以通过有限逻辑格获得；炉/高炉和容器没有因自动传输而产生第二套实现。五槽漏斗的供料、供燃料、抽取、多个连接、失败、循环及存档已经可运行，核心增量集中在局部面协议与调度。A 仍少方向/传输/保护组合，但为规避这些局部模块而放弃布局及漏斗，目前证据不足；历史 A14/B41 相对点不能继续作为否决 B 的实测依据。

保持项目范围内完整漏斗功能可控的做法是：有限允许方块/逻辑格；同一五槽容器协议；推/拉检查设备面和容量；每tick有界调度/原子移动；派生连接；保留冷却/时序的明确验证合同；自然层与持久层分离；假设布局能力保护。多漏斗串联/环是现有许可实例邻接的结果，不引入完整Minecraft世界、掉落实体物理、红石网络或箱子放置。最终区域、数量上限和视图不由70格测试夹具替产品定稿。

|-------------------------------------------------------|----------------------------------------------------------------------------------------------|
