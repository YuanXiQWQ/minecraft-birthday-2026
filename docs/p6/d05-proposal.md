## 2. 推荐合同的共同条款

下列共同条款已由用户明确批准，是**项目适配合同**；其中原版已核实的部分见上节，不能把“保留材料”“无限续燃”称为原版生存规则。

1. **预览与取得分开。** 正确摆格只产生可视预览；不改变永久解锁、配方发现或主页完成事实。手动制作不依赖D06发现状态。结果在事务提交时重新匹配当前输入，而非相信UI传入的结果ID或数量。
2. **合成保留输入。** 每次成功制作保留所有输入格的完整ItemStack、数量及组件；同一已解锁材料可占多个配方格。拖动、取回、漏斗运输等普通临时组移动仍减少源组，不能把运输也变成无限复制。材料/工具的永久资格不减少，不产生耐久消耗。
3. **左/右键完整领取。** 左键或右键结果槽，各向空光标或同组件且容量足够的光标领取一个完整原版结果批次；右键不是拆半、不是只拿1。光标持不同物品或同物品不同组件时拒绝，不交换进去；不足整批容量时无变化。结果槽不可放入、不可作为拖动目标。
4. **结果快捷操作。** 数字1–9/F仅向指定快捷栏格/副手尝试领取一个完整批次：目标空或同组件且整批可容纳才成功，不能覆盖/挤走已有组。Shift左/右键只向九格快捷栏有界批量领取，先合并相同组件再填空格，固定顺序为1→9，不填装备/个人输入/工作台输入，不溢到光标。中键复制、中拖、双击收拢及Q/Ctrl+Q在结果预览上不制造产物；不能走普通已解锁目录复制路径绕过本次制作。物品一旦取得，目录的既有无限操作继续有效。这些结果快捷路由是项目明确适配，不宣称完整复刻原版36格背包路由。
5. **Shift完整批次上限。** 仅规划能完整安置的批次；每批数量、槽上限和组件身份都来自26.3。无余留物时最多`floor(可容纳产物数/每批产物数)`批；有可见余留物时还要同时满足其容量。只计算固定有限目标，预先确定上界，不以永不减少的输入为循环终止条件。只剩6格木板容量、每批4，则只给4，不丢另外2、不偷偷发第二批部分产物。
6. **原子取得与顺序。** 成功提交“目标载体变更＋必要解锁＋工作台内容更新”为一次共享锁内的版本化领域事务；第一次领取主产物才追加永久解锁并发首次事件，重复领取不重复首次通知。若同批有首次取得余留物，顺序为主产物先、再按输入格行优先顺序去重登记余留物，保证副产物首次顺序可重现。冲突、失效实例、目标不足、未知组件/能力、写入失败、重置旧代次均不能只解锁不交付；不拆成UI先取组再单独unlock。
7. **关闭与在途事务。** 延续D07：关闭取消未提交手势/请求及本页光标回执，已进入提交且成功保存的稳定事务不因关闭而回滚；迟到回执不得重新填充已关闭个人界面。仅个人2×2关闭清输入；工作台9格按实例持久，关闭/切场景不清；刷新恢复工作台，个人输入/光标为空；拆除删实例及内部组，不隐式取得输出。失败提示走外置英文，不能假装已领取。
8. **不拓展组件权限。** 按已核实默认组件、等价身份和上限验证。可达修理结果的默认max_damage等须作可验证的默认值归一，不能简单放开任意容量/装备覆盖；不支持的变体应明确拒绝，不能显示预览后悄悄交付错误组。

## 3. 需要选择的剩余物出口

两方案都不覆盖保留的奶桶输入、不增加有限普通背包、不新建不可见增长数组。用户已选择A；B不执行。

### A：返还折算为永久取得（已批准）

- 成功领取一批主产物的**同一事务**中，按原版每占用输入格的余留事实，把余留物视为已经返还取得，加入永久解锁集合；已有解锁则幂等，无额外计数。
- 不创建可见的三个临时桶，也不向九格自动塞桶。出口就是玩家已可无限取用的目录，界面应明确提示实际返还的种类/批次数量，而不是谎报已放到快捷栏。
- 预览、领取失败不返还、不解锁；Shift只对实际提交批次计返还，聚合显示，不产生逐批隐藏库存或无限通知。
- 奶桶前置本已要求取得桶，通常不会产生新解锁通知；仍计算并测试三个桶的原版余留事实，不能干脆删除余留处理。
- 好处：符合无限目录核心，不因已无限拥有空桶却没空快捷格卡住蛋糕；不增加非原版GUI余留槽。代价：余留物不以可见有限组逐个移动，与原版生存的桶回格/回背包不同。

### B：可见临时余留组返入九格（未选择，保留审查选项）

- 先在副本上为整批主产物及全部余留组规划位置。主产物依操作到光标/指定格/Shift九格；余留物只向九格1→9先合并再填空，不填装备、不覆盖输入、不放光标、不drop。
- 任一余留组放不下则该批完全不做；Shift按每批主产物及余留物的联合容量有界，先完整分配每批再继续。没有隐藏余留队列。
- 主产物和余留物各自在成功进入目标载体时才永久取得。已知桶仍生成实际临时组，占用最多16的桶堆叠容量。
- 好处：桶的数目可见、可搬运，容量有明确含义。代价：与原版回输入格仍不同；快捷栏满时，即使光标能放蛋糕也会拒绝整次合成，需要先腾位置。更多容量耦合是明确玩法差异，不是通用正确性所必需。

**推荐A的理由：** 项目资源经济只有取得/未取得，临时数目服务操作体验；无需因为已拥有无限空桶而新增储位门槛。若用户更重视余留组可见移动，B可实现，但必须明确接受满九格阻断合成。

## 4. 炉、高炉与漏斗取得合同（本次只定规则，不实施）

1. 输入与合法燃料的非空有界组作为持续加工引用；实际加工/点燃不减其数量，不改永久资格。手工拿走、替换、漏斗转移仍是有限组移动。燃料并非“每帧重置”：只在可以加工且无余火时按原版燃烧时长开启新周期，周期结束仍有引用且可加工才续燃。
2. 按26.3配方与`cooking_fuel`上下文提供器计算加工tick、燃烧tick、速度；维护原版已点燃余火、无配方/输入/燃料、输出满/组件不合、冷却与停止的状态分支，不把无限燃料改成瞬间完成。输出满时不启新燃烧周期、不能累计超容产物；已经点燃的余火按原版继续消逝，不能把阻塞误称冻结全部计时。具体活跃/后台/离线时钟属D08待审。
3. 加工完的产物留在该实例输出槽，可尚未永久解锁；仅完成计时、看见输出或打开GUI不授予。手动从输出实际转到合法玩家载体的数量，或漏斗成功转移的数量，才构成取得。炉输出是已生产的有限组，左右键按普通输出槽整组/拆半和目标容量移动，**不套用合成预览每次创造整批规则**。
4. 漏斗五槽/原版端口的合法转移是原子源减、目标增；源空、目标满、不兼容或连接失效不取得。输出首次成功转入漏斗等合法实例容器即解锁，不必等再点GUI；失败尝试不提前解锁。移动已知物品只改临时组。未领取新产物可以存在于生产者输出，不可据此让锁定目录或预设越权复制。
5. 当前34种可达燃料无余留物，不能伪造已验证的熔岩桶链。未来来源若引入有余留物燃料：A在一次有效点燃提交时把燃料余留折算为永久返还（不同于主加工产物仍须取得）；B必须先为该燃料余留确定有界可见实例出口及原版端口，不能借玩家不在场时写快捷栏，也不能擅增隐藏队列。**选择B时，这类新燃料的出口须在扩展可达来源前另审；当前来源不受阻。**
6. 设备内部持久化、拆除删内容且不自动领取执行D07。D05不自动批准多标签双倍推进计时、离线产出或配方发现，这些不得由后续实现顺手决定。
