# P6 合成回执输入竞态定向修复

日期：2026-10-21。修复基线：`86d66b77d056e6f96bb6e6e8dd2ba65291ef09b1`。不改变D04、D05/A目录返还、D07，不实现其他P6业务。历史交付及其原始证据保留。

## 根因与正式复现

`takeResult()`没有乐观授物，等待`SaveSession.takeCraft()`的真实提交回执；普通`command()`却在调用时捕获光标、个人四格、expectedLayout，再排队。串行执行事务并不保证调用时捕获的页内光标仍然有效。空槽点击捕获空光标，排在领取之后，最终通过普通回执把四个木板覆盖为空。配方匹配、原子解锁和目录余留规则没有出错。

两种复现均完成：

- `app/tests/crafting-queue.test.ts`调用正式GameInventory/InventoryInput原型方法和真实SaveSession/领域规则/封装校验，仅替换显示、存储及独占锁端口。未复制UI方法体。修复前首项真实失败保留在`evidence/receipt-race/before-unit.log`。
- 浏览器使用正式GameInventory构造器、原版GUI、真实Web Locks/localStorage。仅验证入口包装真实`SaveSession.takeCraft()`，在实际事务提交、释放锁之后延迟返回回执；非伪造授物。`before-*.json`记录原始错误，`after-*.json`记录相同操作修复结果。

| 同一2×2用例 | 修复前 | 修复后 |
| --- | --- | --- |
| 初始 | 四格放1原木；光标空；九格空；只解锁原木 | 相同 |
| 点击结果后等待 | 实际回执4木板；木板已原子解锁；UI光标仍空 | 相同；acquiring=true |
| 等待时点击空九格 | 捕获空光标并排队 | 拒绝，不排队 |
| 释放回执并完成队列 | 光标空、九格空，4木板丢失 | 光标4木板、九格空，门禁解除 |
| 完成后重新点击九格 | — | 光标空、目标格4木板，稳定存档包含4木板 |

浏览器存档、光标、目标槽、解锁及事件记录均在同名JSON中；`evidence-assertions.json`是对这些观察记录的断言摘要，截图不是唯一验收依据。

## 局部修复

生产修改仅限`app/web/src/ui/inventory.ts`与`inventory-input.ts`。不修改SaveSession、领域合成算法、数据、资源或存档版本。

1. `takeResult()`同步创建专属对象票据，持有载体门禁。`command()`在捕获任何页内状态之前统一拒绝门禁期间的修改。
2. 普通格、无限目录、装备、副手、外侧丢弃、数字/F/Q、预设、Shift/双击/克隆/拖动及选择操作都经过该入口。结果入口自身仍阻止重复领取；不依赖按钮视觉禁用。
3. 输入路由在等待期间不建立指针手势，取消已有手势/快捷键暂态。完成时取消领取所属手势，等待中按下、完成后才松开的动作不会变成针对新光标的点击/拖动。不缓存或重放被拒绝输入。
4. E/Esc/Done可关闭。D07清光标/四格并推进个人epoch；成功的稳定提交不回滚。关闭、代次重置、当前设备失效、pagehide/dispose清理或使门禁失效；旧任务只可释放自身票据，不能释放别的领取门禁。
5. 门禁仅用于结果回执未定区间。没有领取时，原有乐观连续槽位命令继续排队。写失败、布局冲突后门禁释放，可刷新/重试；没有全局长时间输入锁或生产延迟。

## 可复现步骤

1. `npm --prefix app run dev:verify`，打开同源`/__verify__/index.html`及`/__verify__/input.html`；只使用此隔离源的可重置存档。
2. 夹具重置进度并解锁原木；游戏E打开个人Crafting，目录取一原木放入四格，确认光标空、九格空、预览4木板。
3. 夹具点击“Arm next crafting receipt delay”，回游戏点击结果；等待记录器receiptDelay.phase=waiting。点击空九格，再点击目录或按数字/F/Q。
4. 夹具“Release crafting receipt”。光标应保留4木板、九格不变、木板已解锁、acquiring=false。重新点击空格，应把4木板存入该格。
5. 同例用3×3工作台或已有同类光标重复；等待时Done/E/Esc关闭，释放后不得复活个人状态。规则测试命令：`node --experimental-transform-types --test app/tests/crafting-queue.test.ts`。
6. 实体跨等待拖动需人工将鼠标按住，另一验证标签释放回执后再松开，确认无意外操作；右/中键及跨浏览器待人工执行。工具不支持的实体操作不反复模拟宣称通过。

结论：目标竞态已在正式方法和真实浏览器复现并通过局部门禁修复；被拒绝输入需在回执完成后重新操作。没有新增炉、漏斗、配方书或其他阶段功能。交付后停止，等待独立审查。
