# 分阶段开发路线与验收

日期：2026-10-20。状态：总体路线已初审通过，P1 分析交付见 [P1 报告](p1/report.md)；具体适配仍待审，P2 未授权。以下各阶段定义供审查与执行时使用，不因前阶段交付而自动进入下一阶段。

依据：[需求核对](requirements-audit.md)、[总体架构](architecture.md)、[决策与调研](decisions-and-research.md)。U 编号见需求核对表。每个阶段完成后形成可独立审查的结果；需审批的门槛未收敛时只做不依赖该决定的工作，不擅自缩范围绕过。

## 1. 依赖和顺序

| 阶段 | 主题 | 直接前置 | 主要风险提前量 |
| --- | --- | --- | --- |
| P1 | 原版数据、资产和 GUI 可行性及行为合同 | 用户审核本轮规划，并授权 P1 | 最先暴露素材分发、版本变化、配方范围、输入与放置复杂度 |
| P2 | 最小工程基线与 GUI/庆典技术验证 | P1 的资产、行为与栈选型门槛 | 先证实原版画面、音效、输入与粒子性能可交付 |
| P3 | 状态内核、存档、本地化、双入口 | P2；P1 状态适配决定 | 避免到完整游戏后才发现进度同步和恢复模型错误 |
| P4 | 原版数据规范化、闭包与配方引擎 | P3 的数据/状态接口；P1 固定来源清单 | 完整规则先于大量内容 UI，尽早发现副产物扩张 |
| P5 | 背包、快捷栏、装备与全部适用 GUI 操作 | P4；P2 输入验证；P3 存档 | 最复杂交互作为独立可审查功能，不埋在场景代码里 |
| P6 | 工作台、熔炉、高炉、配方书 | P5；P4 完整加工数据 | 在接入四场景前验证加工、燃料、剩余物和有界输出 |
| P7 | 四场景、种植、放置、补货及防软锁 | P6；P1 放置结论 | 将工作站与资源接起来，验证全部来源和持久变化 |
| P8 | 主页故事、蛋糕完成、正式庆典与体验定稿 | P7；P2 庆典验证；祝福等体验决定 | 接入已验证的演出，不把烟花可行性留到最后 |
| P9 | 完整回归、构建隔离、Pages 发布候选 | P8 与全部适用决策收敛 | 发布前验证子路径、真实音频、产物隐私与许可记录 |

P2 的技术验证不代表删减后的 MVP；其产物验证高风险基础，最终仍须覆盖全部已明确需求。P4 数据导出可在 P3 接口稳定后独立开展，但不因此安排多代理或多会话操作同一仓库。

## 2. P1：原版证据和行为合同

**目标与范围**：固定 26.3，验证来源与使用条件；完成小样本规则核对、导出方案及 GUI/放置评估。P1 只做来源分析、类型盘点与关键样本，完整递归闭包引擎属于 P4。当前已授权并完成官方下载及隔离静态分析；没有应用原型、客户端运行或额外工具安装，详见 P1 报告。

**前置**：本轮规划通过审核；对不能仅凭工程判断决定的事项获取用户选择。

**主要模块/交付**：版本锁清单、资产来源与使用表、场景原始来源表、物品/配方类型盘点、GUI 输入真值表、无限物品行为合同、A/B 放置评估记录、目标浏览器表。均先保留开发资料；不会直接发布原始游戏构件。

**必须满足及验收标准**：U03、U05–U08、U11、U12、U15、U16。

- Mojang 清单与对应构件/索引可定位并校验；单一版本/名称体系，记录哪些行为还需实际运行核对。
- 分别确认 GUI/字体/图标/粒子/声音/音乐的取得、转换和分发边界；未解决类别明确标记，不能默认可公开分发。
- 核对高风险样本：原木→木板，木镐→圆石，石镐/错误工具→铁矿掉落，桶/奶桶上限，蛋糕格局与剩余物，原木→木炭，木棍/木工具燃料，铁甲回收，高炉适用性及 26.3 实际速度计算。
- 盘点同版本所有配方类型，列出从拟定场景源可能可达的特殊类型，不承诺“只有有序/无序配方”。
- GUI 真值表覆盖下列组，并记录原版生存/创造来源、项目适配和待核实项：取放/拆半、均分拖动、中键复制、收拢双击、Shift 移动/双击、数字键、F、E/Esc、滚轮、结果槽、盔甲、配方书、Q/整组丢弃、C/X 预设适用性、关闭/失焦。
- A/B 成本比较包括漏斗 GUI/传输、侧面输入、输出拥塞、拆换、补货遮挡、存档与最后资源保护；仅评估坐标放置不足以结束评估。
- 临时容器计数、产物取得时机、Shift 有界策略、余留物、退出与离线规则写成可测试输入/输出范例，提交用户审查。

**自动化与人工验证**：获准后用只读数据解析校验样本、来源哈希和缺失项；与真实 26.3 客户端对照操作并录制短输入序列/参考截图。自动提取结果不能作为自身唯一正确性证据。此阶段允许验收条目尚标为“需 P2 原型验证”，但不得把它们标为已通过。

**风险**：某资产分发方式不成立；同版本资源结构/燃料组件与旧工具不兼容；无限规则与原版批量语义冲突；自由网格的漏斗增量超预期；用户设备缺少中键等输入。

**完成判定**：来源和能力表可复核、阻止开工的决策已收敛；放置方案有成本依据并获审查；GUI 合同没有核心含糊项；可列出 P2 的具体技术验证清单。若资源分发等仍未解决，报告具体阻点，不擅自改用自造素材或推进依赖该类资产的阶段。

## 3. P2：工程基线与高风险技术验证

**目标与范围**：在授权后建立最小 Vite/React/TypeScript 工程与测试设施，使用已允许资源验证原版 UI、容器输入、物品图标、烟花与音频。验证一个局部场景，不开发完整四场景内容。

**前置**：P1 中资产使用、工具链、输入适配、放置验证范围已明确。

**主要模块/交付**：构建入口、资源加载适配、原版 GUI 基元、输入试验页、Canvas 粒子/音频验证、局部场景遮挡样本、测试运行配置、实测报告。试验入口仅开发/测试构建可达。

**必须满足及验收标准**：U07、U11、U12、U13、U16。

- 两静态入口在根路径与仓库子路径均能直开；主页不会加载全部游戏试验逻辑。
- 原版槽位/按钮/字体/Tooltip 在整数 GUI 缩放及常见 DPR 下可读、无贴图模糊和错位。
- 至少覆盖平面物品、方块图标、模型/多层物品、动画或特殊资源样本；明确无法直接由 PNG 表示的资源处理方式。
- 左右中键、拖动、修饰键、取消、搜索焦点能经浏览器交付；形成实际限制清单。
- 五种烟花形状及 trail/twinkle 能逐项展示；使用原版粒子、原版声音及可核对的运动/时序；不以通用彩纸库代替。
- 游戏页面首次用户手势后声音正常；直开游戏、音频被拦截、切后台和恢复均有可验证行为。
- 局部场景验证采集消失无背景残影、工作站可替换、热区缩放一致；若 P1 未能实测放置差异，此处完成 A/B 原型并回到用户定案。
- 测得图标/场景/音频体积、音频解码成本与烟花帧时间；冻结目标设备、DPR、粒子并发和帧率预算，而不是仅凭开发机肉眼判断。

**自动化与人工验证**：浏览器真实 pointer/key 序列、GUI 截图基准、固定时钟/随机种子粒子截图与状态断言、资源请求错误统计、音频事件调度断言。人工对照游戏观感与声音，在至少目标浏览器用实体鼠标测试中键和滚轮。截图不替代音频试听。

**风险**：图标生成/字体宽度不符；Canvas 粒子重绘过多；OGG 等音频兼容差异；浏览器保留快捷键；背景与动态元素难分层。

**完成判定**：关键效果与输入均有可复现验证；没有必须重写渲染/事件层的开放问题；确定 Canvas 2D 是否足够，性能需要调整时先处理再进入内容开发。试验完成不能把测试授予物品入口带入生产。

## 4. P3：状态、存档、本地化和页面隔离

**目标与范围**：建立可独立测试的命令/状态/事件结构，以及双入口共用存档与英语本地化。不把真实完整资源流程接入页面。

**前置**：P2 的工具链和适配层通过；P1 无限与时间语义获审查。

**主要模块/交付**：application 命令层、解锁目录、存档适配器及迁移信封、时钟接口、本地化解析器、生日配置、主页只读投影、重置与跨文档协调。

**必须满足及验收标准**：U03–U05、U09、U13–U16。

- 解锁唯一且单调，主线固定位置、副产物首次顺序稳定；重载不会重新发布首次解锁事件。
- 快捷栏、装备、工作站和作物具备版本化保存结构；自然层和玩家持久层分离。
- 核对存储拒绝、损坏、未来 schema、未知 ID、数量越界、迁移失败与上一份有效快照，均不静默覆盖原档。
- 主页/游戏共用一个完成事实；pageshow、storage、返回主页、刷新均一致。
- 重置仅影响项目命名空间，恢复空桌；旧游戏标签不能把重置前的进度写回。
- 单写入协调在目标浏览器实测；无锁能力时不能声称 revision 比较即可保证并发正确。
- 所有界面文本、HTML 标题和可访问性文本外置；缺键可被测试发现，默认英文。

**自动化与人工验证**：纯状态不变量、迁移样本、注入故障存储、两个浏览器页面并行读写/重置、BFCache 返回、禁用存储和隐私模式验证；伪本地化检查长文本。测试数据只在测试构建使用。

**风险**：localStorage 同源跨仓库冲突；旧标签覆盖新状态；把完成和播放状态混为一谈；时间戳受系统时钟影响；迁移自动删失数据。

**完成判定**：独立的状态/存档测试通过，任一存储错误有清晰用户反馈；两入口在同一存档契约下工作。尚无真实主线不妨碍本阶段独立验收。

## 5. P4：原版数据包、闭包和配方内核

**目标与范围**：完成所选场景源的全量可达物品/配方/燃料/加工/资产清单，落地数据规范化和纯规则处理。此阶段不得退化为手工主线白名单。

**前置**：P1 固定版本、场景来源及允许能力；P3 数据与解锁接口稳定。

**主要模块/交付**：开发期导出器与版本锁、规范化数据包、ingredient/tag/component 解释器、有序/无序及可达特殊配方处理器、工具/燃料数据、闭包来源报告、配方书发现映射。

**必须满足及验收标准**：U03、U06–U08、U10、U11。

- 每个可达物品有来源证明；工作站自身材料与燃料能力都参与推导，不靠循环凭空解锁高炉。
- 标签递归、配方镜像/偏移、重复材料、输出 count、余留物、2×2/3×3 适用性准确。
- 正确工具与掉落分开，错误工具不授予掉落；不以总材质等级代替原版标签。
- 原木→木炭、圆石→石头→平滑石、铁装备→铁粒→铁锭等实际可达规则按同版本验证；新产物继续参与闭包。
- 可达普通合成全覆盖；排除切石机等功能不排除该方块的合成。没有钻石来源就不制造钻石主线或配方要求。
- cooking_fuel 和上下文速度解析正确；高炉未硬编码重复减半；木棍/木工具等合法燃料纳入。
- 未知可达类型与丢失资源使构建校验失败，不静默跳过；完整覆盖报告可审查。
- 配方可用、配方书发现与取得产物三者分离。

**自动化与人工验证**：对官方样本建立独立 golden fixtures；生成闭包与来源证明，检查可达配方没有漏实现；对随机摆格与标签等价物做属性测试；人工在目标游戏中核对高风险及分层抽样副产物。可重复导出比较稳定哈希。

**风险**：特殊配方/组件变体扩大范围；模型资源不闭合；错误处理标签或速度上下文；错误选择源元素引入大量不必要分支。

**完成判定**：所有可达项都有已支持处理器及资源/文本映射；工作站边界符合用户规则；闭包可以从零证明蛋糕可达。发现新增能力冲突先审查，不能为过关过滤掉要求覆盖的配方。

## 6. P5：目录、快捷栏、装备和输入行为

**目标与范围**：完成可交互的原版容器操作层，在测试场景独立验证背包与装备，不依赖完整世界内容。

**前置**：P4 堆叠/装备/物品身份数据；P3 存档与解锁；P2 输入技术验证。

**主要模块/交付**：SlotPolicy、ItemStack 适配、光标/拖动状态机、目录展示、九格快捷栏、装备/副手、Tooltip、个人合成界面壳层、GUI 真值表对应测试。

**必须满足及验收标准**：U03–U05、U07、U11。

- 未解锁目录黑色蒙版、可看 Tooltip、不可通过任何输入路径取出；主线顺序和副产物顺序正确。
- 解锁项是无限源；快捷栏允许重复物品，桶、奶桶、工具等按真实上限；无真实库存/耐久消耗。
- 完成 P1 所有适用操作行，包含奇数拆半、已有部分堆叠合并、剩余分配、跨非法槽、重复拖过槽、鼠标出界、失焦和关闭取消。
- 数字键悬浮交换与场景选择区分；Shift 目标顺序按界面定义；输出槽只取不放；装备正确并支持空槽右键装备。
- 世界丢弃不新增地面实体；临时丢弃不能撤销解锁。C/X、Q 等项目适配具有明确依据和测试，不能无声忽略。
- 输入框编辑不触发游戏键，浏览器快捷键冲突有实际验证与替代入口。

**自动化与人工验证**：真值表每行至少一个状态测试及必要浏览器序列；对移动类命令检查临时数量守恒，对复制类检查目标上限及目录不变；真实按键/鼠标拖动回归；原版 GUI 截图和不同缩放人工对照。

**风险**：浏览器 click/contextmenu/auxclick 重复派发；React 重渲染打断拖动；Shift 循环失控；目录适配与原版背包视觉面积冲突；事件焦点污染。

**完成判定**：适用行为矩阵无未实现行，无目录越权、非法槽位、超上限或无限循环；复杂操作不依赖场景私有逻辑。以“鼠标能拖进去”作为验收不足。

## 7. P6：功能工作站与配方书

**目标与范围**：完成个人 2×2、工作台、熔炉、高炉以及原版配方书；支持所有可达加工和替代燃料。

**前置**：P4 配方与加工数据；P5 容器协议；P3 时钟与存档。

**主要模块/交付**：crafting processor、cooking processor、station definitions/instances、工作站 GUI、发现触发器、配方书和 Toast、结果与余留物策略。

**必须满足及验收标准**：U03、U06–U08、U11。

- 2×2 和 3×3 能力正确，手工匹配不受配方发现状态限制。
- 书内分类、搜索、筛选、分页、配方变体、幽灵填充及 Shift 行为符合适用矩阵；已解锁材料可重复填入，不要总数量。
- 手动槽位接受、Shift 路由与实际加工分别遵循原版：输入槽可暂放不可加工物；Shift 按该站配方/燃料路由；高炉不把原木加工成木炭。
- 所有可达合法燃料生效，短燃料循环可完成加工；时长、速度、火焰/箭头及结果 count 正确。
- 加工和结果领取不消费永久物品；输入保留，批量动作受目标容量限制；输出满停止，无无限通知和经验音。
- 首次取得产物才解锁，或采用经审批的替代合同；刷新中途、切场景、关闭 GUI 后内容和计时按合同保持。
- 设备实例隔离；拆换不会把旧计时/输出混进新设备。

**自动化与人工验证**：固定时钟逐步推进；非法燃料/输入、换燃料、输出堵塞、短燃料续燃、重新加载、重复领取不重复解锁；对书内所有可达配方做可填充验证；人工对比真实熔炉/高炉与 GUI 操作。

**风险**：原版上下文燃料速度解析错误；不消耗输入导致 Shift/连续输出死循环；剩余物覆盖输入；配方书本地化搜索与发现缺口。

**完成判定**：所有已纳入工作站的配方/燃料覆盖验证通过，GUI 行为矩阵对应行通过，结果不会因中断丢失或越权产生。漏斗仍按 P1 结论在 P7 纳入，不提前假定排除。

## 8. P7：四场景与完整资源流程
