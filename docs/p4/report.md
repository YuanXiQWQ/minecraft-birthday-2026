## 4. 来源、闭包与限制

基线采用与P3既有ID一致的“橡木＋普通蛋”候选，**不据此定稿P7树种/鸡变体/位置**。起点为可交互树干、草、甘蔗、石头/煤矿/铁矿、鸡旁固定蛋、成年牛、预耕地小麦。草种子保持原表0.125正概率，闭包表示存在取得路径，不声称一次点击必掉或固定次数保证；小麦成熟age7，不规定离线计时。

闭包逐轮从实际来源、工具、工作台、炉/高炉、合法燃料、结果与剩余物推导；不存在的前置不能通过循环生成。**113种完整物品集合及逐项因果证明**见coverage的proofs；新副产物继续参加推导。包括铁矛、名牌、草床、陷阱箱、矿车、剪刀/草物品等，不是人工主线白名单。箱子/切石机等可合成不表示可放置或使用；持久Kind仍只有工作台、熔炉、高炉、漏斗。

剪刀对已有可交互草启用原版分支，不额外开放背景树叶、泥土、水或杀牛鸡；剥皮/精准采集/附魔/堆肥/交易等没有来源或能力，不添加。原木、矿石、草和小麦的潜在掉落由原JSON分支取得；3种矿洞来源的正确工具标志再次从Blocks注册核实，不靠名称或速度猜等级。金镐速度高仍不能取得铁矿掉落。

另对原版标签导出的10种未剥皮可燃原木（含26.3的poplar）和蓝/棕蛋做12个[候选来源配置](../../data/minecraft/26.3/source-profiles.json)。各配置都有完整物品证明、112条可达配方并在测试中实际执行匹配/蛋糕链。它们不全部并入当前永久注册表，更不自动成为场景采集资源；P7选择或增加来源时应重新生成注册表并审查存档兼容。

## 5. 匹配、组件与加工合同

- 有序：原pattern/key大小写、外圈空白裁剪、2×2/3×3合法偏移、水平镜像及全部空位；不接受2×3等非本项目原版菜单。
- 无序：重复材料和重叠标签使用不同槽位的二分匹配，单格堆叠不能代替多个配方格。
- `findCrafting`在已支持的运行集合中查询，`matchCrafting`验证指定配方；返回结果数量和每格原版剩余物，不发解锁事件、不改存档。蛋糕接受#eggs三种蛋，三个独立奶格返回三个空桶。
- `matchCooking`区分smelting/blasting，输入槽能放下某物不代表能加工；高炉不烧原木。工具/盔甲堆叠、装备槽、耐久身份、燃料来自注册代码和原始标签/提供器，未按名字后缀猜测。
- `componentsMatch`支持已核实的默认堆叠/耐久值及显式JSON组件语义相等；复杂默认组件值未解释时抛出明确错误。结果组件保留。修理支持同物品、每格1件、原版耐久组件公式，未损坏工具也可匹配；当前来源无法产生的任意自定义/诅咒等修理变体仍明确拒绝，不宣称完整组件引擎。
- 34种可达合法燃料逐项见coverage.fuels，含木棍100tick、木工具200、木板/原木300、木台阶150、煤/炭1600、煤块16000、船1200。快速上下文燃烧时间按原提供器除数、速度按原speed_default解析；200字段在炉/高炉为200/100tick，**不再额外硬减半**。单根木棍100tick不足一次200tick加工，不因此实现项目无限续燃候选。

## 6. 完整蛋糕执行链

[cake-chain.json](../../data/minecraft/26.3/cake-chain.json)包含18步拓扑顺序、实际摆格/加工输入、数量和剩余物；`npm run data:verify`重新执行全部112条可达配方以及该链。

1. 徒手原木→4木板→4木棍；4格木板制作工作台。
2. 工作台：3木板＋2木棍→木镐；石头正确工具分支→圆石。
3. 3圆石＋2木棍→石镐；正确工具采铁矿→粗铁。
4. 8格圆石→熔炉；使用可达原木燃料，粗铁→铁锭。
5. 3格铁锭→桶；成年牛持桶分支→奶桶（永久来源可重复填入三个独立格）。
6. 甘蔗→糖；取得鸡旁蛋；草正概率取得种子→预耕地成熟小麦。
7. 工作台 `AAA/BEB/CCC`：A奶桶、B糖、E #eggs、C小麦→1蛋糕，原版事实产生3桶剩余物。

高炉不作为第一个铁锭的循环前置：先由普通炉取得铁，再取得平滑石并合成高炉。熔炉原木→炭、圆石→石头→平滑石、两炉粗铁加工与铁装备→铁粒→九格铁粒还原铁锭均有独立样本。**推导链止于蛋糕物品，不触发生日完成；正式结局仍必须在P8将蛋糕放到家中桌上。**
